# 19 · 服务器详情页扩展：标记 / 防火墙 / IP（网卡）/ PBR

> 状态：待老婆拍板
> 范围：Stella 服务器监控模块，在节点详情页新增 4 个能力

---

## 1. 需求概述

在服务器详情页新增三块 + 一个归类：

| 模块 | 一句话 |
|---|---|
| 标记 | 标内网/公网；公网服务器自动获取或手动输入公网 IP，展示 `IP -- [IPv4] -- 地区`（中文） |
| 防火墙 | 自动检测 iptables / UFW 并接入，可查看配置、可修改（含持久化） |
| IP（网卡） | 识别物理网卡、默认隐藏 docker 网卡（可勾选显示）、改 IP 二次确认 + ping 回退 |
| PBR | 归类到 IP 模块「路由/策略路由」子项（`ip rule` + 多路由表） |

已拍板决策：
- 公网 IP 获取：**双服务 + fallback**；地区**中文**
- 防火墙：**iptables + UFW 都支持修改**，修改后**持久化**
- 改 IP：**临时 `ip addr` 改 → ping 通 → 写持久化；不通 → agent 本地 `ip addr` 回退**（非中心下发回退，因可能断网）
- 改 IP / 防火墙修改：**都要红色「危险操作」警告条**
- IP 持久化：**agent 自动适配** netplan / NetworkManager / networkd
- iptables 修改：**双入口**（表单 + 原文编辑）
- PBR：**本期只读**

## 2. 标记模块

### 2.1 数据字段（nodes 表新增）

```
net_type         enum('internal','public')  -- 内网/公网
public_ip        varchar(64) NULL           -- 公网 IP
public_ip_source enum('auto','manual') NULL -- 自动/手动
ip_version       enum('IPv4','IPv6') NULL   -- IP 类型
region           varchar(64) NULL           -- 地区（中文）
```

### 2.2 公网 IP 自动获取（双服务 + fallback）

**由 agent 端获取**（agent 在服务器上，能拿到服务器真实出口 IP）：

```
主：ip-api.com   GET http://ip-api.com/json/?lang=zh-CN
    → { query:"1.2.3.4", country:"中国", regionName:"香港", city:"..." }
备：ipinfo.io    GET https://ipinfo.io/json
    → { ip:"1.2.3.4", country:"HK", region:"Hong Kong", city:"..." }
```

- 主服务返回中文（`lang=zh-CN`），备服务返回英文，需一张「国家/地区英文→中文」映射表兜底
- agent 首次上报 + 手动触发「重新探测」时获取，结果写入 `public_ip / ip_version / region`
- 手动输入：前端填 IP → 后端调 `ip-api.com/json/{ip}?lang=zh-CN` 查地区（失败则 ipinfo fallback）

### 2.3 展示格式

```
149.104.15.68 -- [IPv4] -- 香港
192.168.1.6   -- [IPv4] -- 内网（不显示地区）
```

## 3. 防火墙模块

### 3.1 检测（agent 端，扩展 `_check_components`）

```
ufw       = which ufw 且 ufw status 可执行
iptables  = which iptables 且 iptables --version
firewalld = which firewalld（仅检测，本期不接入）
```

上报 `components.firewall = { ufw: bool, iptables: bool }`

### 3.2 查看配置（只读，安全）

- UFW：`ufw status verbose`（规则）+ `cat /etc/ufw/ufw.conf` + `/etc/ufw/user.rules`
- iptables：`iptables -L -n -v --line-numbers` + `iptables -t nat -L -n -v` + `iptables-save`

前端按「规则列表 + 原始配置」两个 tab 展示。

### 3.3 修改（危险操作，红色警告条 + 二次确认）

**双入口**：

1. **表单**：选「表（filter/nat/mangle）+ 链」，按表动态出字段——
   - filter 放行/拒绝：链 + 协议 + 端口 + 动作
   - nat 端口映射：目的 IP:端口 + 目标 IP:端口（DNAT）
   拼接成命令由 agent 执行
2. **原文编辑**：直接改 `iptables-save` / `ufw` 配置文件全文，懂行贴规则，覆盖全部 5 表

**持久化**：
- UFW：规则自动持久化（无需额外处理）
- iptables：`iptables-save > /etc/iptables/rules.v4`（v6 同理）

修改前红色警告条 + 二次确认；执行后回显结果。

### 3.4 未检测到防火墙的情况

- UFW 未装（Arch/CentOS 常见）→ 显示「未检测到 UFW」+ 代装入口（`apt install ufw`，装完默认 disabled，安全）
- iptables 命令行工具未装（新系统默认 nftables）→ 显示「未检测到 iptables」+ 代装入口
- 两者皆无 → 提示「本机未检测到防火墙工具」
- 代装复用组件代装机制（`install-component`）

## 4. IP 模块（网卡）

### 4.1 网卡识别（沿用 8.14 已认可标准）

```
物理网卡：/sys/class/net/{iface}/device 存在（PCI 设备）
虚拟网卡：veth*/docker*/br-*/tun*/cni*/lo 等
```

- 扩展 `list_interfaces()`：每网卡带 `physical`（bool）+ `docker`（bool，匹配 docker0/veth*/br-*）
- 前端默认**隐藏 docker 网卡**，提供「显示虚拟/容器网卡」勾选开关
- 每网卡显示：名称 / 物理·虚拟标签 / IP 地址 / 状态

### 4.2 改 IP（高危 + 二次确认 + ping 回退）

**表单**：网卡（下拉，仅物理网卡可改）+ 新 IP + 子网掩码 + 网关（可选）+ 预计可 ping 目标（必填）。

**回退时序（agent 本地自包含，不依赖中心）**：

```
① 前端：红色警告条 + 二次确认 + 填「预计可 ping 的 IP/域名」
② 后端：下发「改 IP 任务」给 agent（新IP/掩码/网关/ping目标）
③ agent 本地备份：
     a. 当前 ip addr 状态（旧 IP + 掩码）
     b. 旧持久化配置原文（netplan/networkd 文件内容）
④ agent 临时应用新 IP：ip addr del 旧/掩码 dev X && ip addr add 新/掩码 dev X
   （改网关则：ip route del default && ip route add default via 网关）
⑤ 等 2~3 秒让网络生效
⑥ agent 本地 ping 测试：ping -c 3 -W 2 <目标>
⑦ 判定：
     ├─ 通 → 写持久化（netplan/networkd）→ 上报「成功」
     └─ 不通 → 本地回退：ip addr del 新 && ip addr add 旧（网关同理）
              → 恢复持久化文件原文 → 上报「失败，已回退」
```

**关键**：第 ④~⑦ 步全在 agent 本地执行。改 IP 后若断网，中心已连不上服务器，**回退只能靠 agent 自己**——所以回退逻辑必须随任务一起下发、agent 本地跑完，绝不依赖「中心再发一条回退指令」。

### 4.3 持久化自动适配（agent 检测，按顺序）

> netplan 必须排在 networkd 前面——HK 那种 netplan 后端就是 networkd，先判 networkd 会误判去写 `.network` 文件，但真正生效的是 netplan yaml。

```
① netplan 命令存在 且 /etc/netplan/*.yaml 存在  → netplan：写 .yaml + netplan apply
② nmcli 可用 且 NetworkManager active         → NetworkManager：nmcli con mod
③ /etc/systemd/network/*.network 存在 或 networkd active → networkd：写 .network + networkctl reload
```

- 实测：HK VPS = netplan（后端 networkd）；本地 Hermes-workstation（Arch）= NetworkManager
- 三套都探测不到 → 报「无法识别本机网络持久化方式」，仅支持临时 `ip addr` 改（不写持久化）

## 6. 后端 API（新增）

```
GET  /nodes/{id}/net-info            -- 网卡清单（含 physical/docker）+ 防火墙检测 + 公网IP/地区
POST /nodes/{id}/net-type            -- 标记内网/公网 + 手动 IP（后端查地区）
POST /nodes/{id}/public-ip/refresh   -- 触发 agent 重新探测公网 IP
GET  /nodes/{id}/firewall            -- 查看防火墙配置（ufw/iptables 规则 + 原文）
POST /nodes/{id}/firewall/rule       -- 修改防火墙规则（危险，agent 执行 + 持久化）
POST /nodes/{id}/ip-change           -- 改 IP 任务（危险，含回退参数）
```

agent 端对应新增 `_run_firewall` / `_run_ip_change` / `_probe_public_ip` / `_list_net_info`。

## 7. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 改 IP 断网后中心失联，无法下发回退 | 高 | 回退逻辑 agent 本地自包含，随任务一起跑 |
| iptables 改错锁死自己 | 高 | 红色警告条 + 二次确认 + 修改入口默认收起 + 只读视图默认展示 |
| ping 测试目标本身不通（误判） | 中 | 目标必填 + 用户自选「已知可达」目标 + 提示用网关/8.8.8.8 |
| 持久化写一半失败 | 中 | 先备份原文，失败恢复备份 |
| 网关改错导致 ping 走错出口 | 中 | 网关可选，默认不改网关只改 IP |
| ip-api 免费版限流/挂 | 低 | 双服务 fallback + 手动输入兜底 |

## 8. 验收标准

1. 节点标记内网/公网，公网节点展示 `IP -- [IPv4] -- 地区`（中文），自动/手动均可
2. 防火墙检测出 ufw/iptables 状态，能查看规则与原文
3. 防火墙可添加/删除规则并持久化，全程有红色警告条 + 二次确认
4. 网卡清单区分物理/虚拟，docker 网卡默认隐藏、可勾选显示
5. 改 IP 走完整回退链路：二次确认 → 填 ping 目标 → 临时改 → ping 通写持久化 / 不通 agent 本地回退
6. PBR 只读展示 `ip rule` + 路由表
